# 곡소리 개미 월드 — HD-2D 재설계 계획

상태: 계획만 작성. 구현·에셋 생성·커밋·푸시를 시작하는 문서가 아니다.

## 1. 확정된 사용자 의도

- 현재 결과는 그래픽·UX 모두 실패했다. 기존 벡터 디오라마를 기준으로 보수하지 않는다.
- “곡소리”가 느껴져야 한다. 손실, 공포, 체념, 작고 우스운 희망이 공존하는 블랙코미디다.
- 밝은 장난감 마을, 파스텔, 도형으로 조립한 건물·캐릭터는 폐기한다.
- 사용자 지정 그래픽 방향은 **HD-2D**다.
- 별도 레퍼런스는 없다. 사용자에게 스타일 선택 책임을 다시 넘기지 않는다.
- 이번 요청 범위는 후속 구현을 위한 계획이다. Astra로 전환할 경우 이 문서를 작업 기준으로 사용한다.

## 2. 현재 화면에서 확인한 실패

배포 화면을 데스크톱 1440×900, 모바일 390×844에서 확인했다.

- 첫 화면의 공포 비율과 장면의 정서가 연결되지 않는다. 실제 공포 글이 많아도 밝은 잔디와 웃는 개미가 화면을 지배한다.
- 네 건물과 다섯 메뉴가 나열되어 있고, 첫 번째로 무엇을 보면 되는지 알려주지 않는다.
- 모바일 생태계의 종목명은 실제 화면에서 약 6px 높이, 집계 설명은 약 5px 높이로 축소된다.
- 플레이어를 움직여도 새로운 정보나 의미 있는 반응이 없어 조작 이유가 약하다.
- 중요한 글·지수를 감추고, 데이터와 무관한 색상·감정 설정을 상시 노출한다.
- 기능 검사와 rAF 간격을 통과한 사실을 시각 품질·사용성의 증거로 취급했다. 다음 검증에서는 분리한다.

## 3. 그래픽 방향

**새벽의 거래소 골목과 그 아래 개미굴.** 닳은 바닥, 낮은 천장, 오래된 전광판, 비상등, 빈 종이컵, 구겨진 전단, 대피용 짐 같은 생활감으로 세계를 만든다. 과도한 공포물이나 무차별 네온 사이버펑크로 흐르지 않는다.

HD-2D는 2D 픽셀 스프라이트와 3D 공간을 결합하는 방식으로 잡는다. [Square Enix의 공식 설명](https://press.na.square-enix.com/AN-EPIC-ADVENTURE-DRAWS-NEAR-DRAGON-QUEST-III-HD-2D-REMAKE-IS-NOW-AVAI)을 구성 원리의 참고로 사용하되, 기존 게임의 캐릭터·배경·UI는 가져오지 않는다.

- **개미:** 투명 배경 픽셀 스프라이트. 무거운 눈꺼풀, 축 처진 더듬이, 작은 짐, 전단을 쥔 손 등 실루엣과 자세로 감정이 읽혀야 한다. 작게 띄운 말풍선에 감정 전달을 의존하지 않는다.
- **공간:** 픽셀 텍스처를 입힌 실제 3D 바닥·벽·계단·구조물. 앞뒤 가림, 높이 차, 접지 그림자가 존재해야 한다. 배경 한 장을 확대·이동시키는 구성은 채택하지 않는다.
- **빛:** 먹색·차콜·탁한 청회색을 바탕으로 제한된 붉은 경광등과 낡은 황색 조명. 검정 화면에서도 얼굴·이동 경로·상호작용 지점은 구분되어야 한다.
- **후처리:** 발광은 광원 주변만, 심도 효과는 배경·전경 일부만. 정보·인물까지 번지거나 읽기 어려워지면 제거한다.
- **희망:** 같은 어두운 세계 안에서 자세와 작은 빛이 달라진다. 희망 수치가 높아졌다고 장면 전체가 밝은 축제 마을로 변하지 않는다.
- **문자:** 로고·종목명·본문·수치는 선명한 HTML UI로 표시한다. 작은 한글을 스프라이트나 배경 이미지에 구워 넣지 않는다.
- **금지:** 월드 그래픽의 SVG 캐릭터·도형 건물, 이모지 대체 아트, 기본 도형에 블룸만 얹은 배경, 스타일이 다른 에셋 혼합, 생성 이미지의 가짜 UI·가짜 시장 수치.

## 4. 에셋 제작 기준

전체 맵보다 먼저 아래 최소 세트의 원본과 실제 렌더 결과를 맞춘다.

1. 광장 한 구역: 거래소 입구, 개미굴 입구, 전광판, 바닥·벽·계단, 전경 소품.
2. 기본 개미 한 종: 우선 4방향 걷기와 정지. 이후 주저앉기·짐 꾸리기·실랑이·작은 환호를 추가한다.
3. 삐에로 앵커: 같은 픽셀 밀도와 명암 규칙의 별도 캐릭터 시트.
4. 공포·희망·중립에 필요한 소품과 신호: 외형만 봐도 상태가 구분되는 범위로 제한한다.

스프라이트는 원본 픽셀 격자에서 프레임별 실루엣·발 위치·투명 테두리·색상 수를 확인한다. 걷기 중 크기나 얼굴이 바뀌는 시트는 쓰지 않는다. 배경과 캐릭터는 동일한 카메라 각도·픽셀 밀도·조명 방향을 따른다. 콘셉트 이미지와 실제 게임 에셋을 구분한다.

납품 단위는 편집 가능한 원본, PNG/atlas, 3D 모델·텍스처, 애니메이션 정의, 출처·사용 권리 기록이다. 에셋이 확보되지 않은 상태에서 임시 도형으로 네 장면을 완성했다고 보고하지 않는다.

## 5. 첫 화면의 사용 흐름

첫 질문은 **“지금 어디서 곡소리가 나고 있나?”**다.

- 접속 즉시 실제 집계의 공포·희망·표본·기준 시각이 읽힌다. 제목은 현재 데이터에 맞춰 작성하고 임의의 위기·폭락을 단정하지 않는다.
- 첫 화면에 실제 대표 글 일부와 명확한 **‘최근 곡소리 보기’** 동작을 제공한다. 정보 확인을 위해 먼저 건물을 찾아다닐 필요가 없다.
- 월드 속 개미·지역을 선택하면 **선택 대상 → 분위기 → 근거 글**이 한 흐름으로 연결된다.
- 건물·지역은 이름과 기능을 읽을 수 있는 진입 지점을 가진다. 작은 개미 하나를 정확히 눌러야만 정보를 여는 구조는 피한다.
- 아바타 이동은 선택 사항이다. 바닥 클릭·탭과 방향키 이동을 지원하되, 벽을 관통하지 않고 이동 가능한 위치에 도착해야 한다. 이동 중 가까운 지역의 이름·반응이 자연스럽게 나타난다.
- 아바타 설정·효과음·사이트 설정은 보조 메뉴로 옮긴다. 설정이 첫 화면의 핵심 정보와 경쟁하지 않게 한다.
- 효과음은 기본 무음. 분위기를 이해하는 데 음성이 필수여서는 안 된다.

## 6. 네 콘텐츠의 재구성

| 콘텐츠 | 공간과 연출 | 사용자가 얻는 것 |
| --- | --- | --- |
| 개미 생태계 | 종목별 굴이 연결된 지하 거주 구역. 모여드는 개미, 문 닫은 굴, 짐 싸는 개미를 상태별로 배치 | 어떤 종목이 주목받는지, 분위기가 왜 그런지 실제 글로 확인 |
| 희망군 vs 절망군 | 낡은 바리케이드와 대기 진영. 병력·전선·깃발을 데이터로 변화시키고 신규 글에 지원군 반응 | 선택 종목의 희망·공포 비율과 양쪽 근거. 중립 별도 확인 |
| 곡소리 재난방송 | 야간 임시 방송실, 삐에로 앵커와 커뮤니티별 현장 화면 | 커뮤니티 사이의 심리 차이와 관심 종목을 빠르게 파악 |
| 오늘의 개미극장 | 어두운 소극장. 저장 시점에 따라 같은 세계의 조명·군중·사건을 재생 | 날짜별 심리 변화, 마지막 장면 PNG와 공유 링크 |

네 기능은 최종 범위에 유지한다. 그래픽 품질이 확인되기 전에는 네 개의 임시 장면을 병렬로 늘리지 않는다.

극장에 기록이 없으면 기록 시작 조건과 현재 상태를 명확히 표시한다. 빈 극장을 재생 가능한 콘텐츠처럼 내놓지 않는다. 기록 누락은 보간하지 않는다.

## 7. 데스크톱·모바일 UI

- 데스크톱: 월드와 정보 영역을 분명히 나눈다. 글·지수 패널을 열어도 대상 지역을 계속 볼 수 있어야 한다. 지수·피드를 함께 볼 수 있지만 중첩 모달로 캔버스를 덮지 않는다.
- 모바일: 별도 카메라 구도와 지역 선택 목록을 사용한다. 전체 지도를 한 번에 축소하는 방식은 폐기한다. 종목을 목록에서 선택해 해당 굴과 정보를 집중해서 본다.
- 모바일 세부 정보는 하나의 하단 시트에서 전환한다. 닫기·뒤로 가기·현재 선택 상태가 일관되게 동작해야 한다.
- 본문은 기본 14px 이상, 주요 터치 영역은 44px 이상을 목표로 검증한다. 월드 축척 때문에 UI 글자 크기가 줄어들지 않게 한다.
- 원래 피드의 필터·더 보기·원문·예쁜말, 테마·인증·프로필·정책 접근은 유지한다. 다른 페이지의 레이아웃은 이번 재설계 범위에 넣지 않는다.

## 8. 구현 구조

- 기존 Next.js·React 18 유지. Three.js를 월드용 클라이언트 모듈로 동적 로드한다. React는 HUD·패널·데이터 상태를, 렌더 루프는 장면·스프라이트·카메라를 맡는다.
- 캐릭터는 방향별 픽셀 atlas와 billboard/plane으로 구성한다. [Three.js billboard 문서](https://threejs.org/manual/pages/billboards.html)를 참고하되 조명·그림자·가림이 필요한 부분은 그에 맞는 소재·구조를 선택한다.
- 텍스처 확대 필터·정수 배율·서브픽셀 이동 처리를 검증해 픽셀 선명도와 움직임을 함께 맞춘다. [Texture 문서](https://threejs.org/docs/pages/Texture.html) 기준으로 설정을 확인한다.
- 광원·그림자·후처리는 제한된 수로 시작한다. 모바일은 렌더 해상도·효과 품질을 조절한다. [후처리 문서](https://threejs.org/manual/pages/post-processing.html)를 참고해 필요한 패스만 사용한다.
- 장면별 에셋을 필요할 때 로드하고 나갈 때 GPU 자원을 정리한다. 숨김 탭에서는 렌더·폴링·효과음을 멈춘다.
- WebGL 사용 불가·동작 줄이기에서는 같은 아트의 정적 화면과 정보 탐색을 제공한다.

기존 `WorldFrame`, 두 내부 읽기 API, detector register 기록 경로, 스냅샷 마이그레이션과 집계 산식은 재사용한다. 이번 작업에서 새 감성 분류나 추가 LLM 호출을 넣지 않는다. 기록 테이블의 실제 적용 여부는 구현 시작 때 다시 확인한다.

## 9. 작업 순서와 중간 산출물

1. **아트 디렉션 시트:** 팔레트, 카메라 각도, 픽셀 밀도, 캐릭터 비율, 조명 규칙, 대표 소품, 세 가지 분위기 비교. 임시 웹 UI가 아닌 실제 사용할 아트 기준을 만든다.
2. **광장 한 장면 완성:** 실제 에셋·움직임·빛·그림자를 갖춘 동작 화면. 데스크톱과 모바일 실크기 캡처를 만든다. 데이터나 글창 없이 보아도 곡소리의 세계로 읽혀야 한다.
3. **핵심 흐름 완성:** 실제 데이터 → 대상 선택 → 근거 글 확인 → 돌아오기. 초행 사용자 기준으로 길 찾기와 조작을 검증한다.
4. **네 콘텐츠 확장:** 같은 아트 규칙으로 생태계·전장·방송·극장을 연결한다. 장면별 구도와 동작에 차이를 준다.
5. **통합 검증:** 실제 데이터와 빈 데이터, 모바일, 접근성, 그래픽 성능, 기존 기능 회귀를 확인한다. 현재 요청에서 배포는 수행하지 않는다.

## 10. 완료 판정

- 첫 화면에서 ‘곡소리’의 정서, 현재 분위기, 첫 행동을 설명 없이 파악할 수 있다.
- 픽셀 캐릭터·텍스처·입체 공간·접지·조명이 하나의 아트 스타일로 보인다. 조명으로 어둡게 가린 도형 마을이면 탈락이다.
- 공포·희망·중립은 실제 수치와 일치한다. 분위기를 내려고 데이터를 왜곡하거나 가짜 글·가짜 가격 차트를 만들지 않는다.
- 화면 전체 축소 없이 모바일에서 종목명·본문을 읽고 대상을 누를 수 있다.
- 네 콘텐츠의 진입 이유와 선택 후 결과가 명확하고, 필수 정보에 불필요한 이동·중첩 팝업이 없다.
- Chromium·Firefox의 실제 렌더 프레임과 프레임 시간을 확인한다. 목표 데스크톱 60fps·모바일 30fps. rAF 콜백 빈도만으로 달성했다고 보고하지 않는다.
- 최대 48개/24개 개미 상태, 이동·패널·시간 탐색 중 성능을 각각 확인한다. 실제 기기와 viewport 모의 측정을 구분한다.
- 로컬·개발 서버·최적화 빌드·운영 검증 결과를 따로 기록한다. 실제 동작 화면을 최종 증거로 남긴다.

## Astra 인계 지침

기준 커밋은 `2e86a0d`다. 사용자가 거부한 현재 화면을 참고 시안으로 재활용하지 말고, 사용자 피드백과 본 계획의 정서·아트·UX 기준부터 적용한다. 첫 구현 목표는 광장 한 장면과 근거 글 확인 흐름이다. 에셋 품질·실크기 화면 검토가 끝나기 전에 전체 기능을 임시 그래픽으로 다시 채우지 않는다. 사용자가 구현을 요청하기 전까지는 계획 작업만 진행한다.
