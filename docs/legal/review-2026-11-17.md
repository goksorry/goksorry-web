# 2026-11-17 약관·개인정보처리방침 개정

현재 운영과 확인된 코드·설정을 기준으로 두 문서를 전면 정비했다. 광고 도입은 이번 작업 범위에 없다. 이 변경이 외부 출처의 수집 허락이나 개인정보 처리의 법적 적합성을 모두 확보했다는 의미는 아니다.

## 공개와 시행

- 공고: 운영 DB migration 027 적용 시각. 기존 문서와 동의 시각은 유지한다.
- 예정 시행: 2026-11-25 00:00:00 KST. 늦게 적용하는 환경에서는 최소 7일의 공지기간이 확보되도록 시행일을 자동으로 뒤로 잡는다.
- 이용약관 개정본: `/terms?version=8b52c24b-bf91-4a62-b542-fb2c5fe2b317`
- 개인정보처리방침 개정본: `/privacy?version=a59af39c-a758-4a8f-878a-a9bf5634ba17`
- 현행 URL은 시행시각 전까지 기존 DB 문서를 표시하고, 이후 새 문서로 전환한다. 두 개정 공지를 동시에 표시하며 버전별 전문과 변경 이력을 제공한다.
- 이 개정 공지 자체로 추가 목적이나 국외 이전의 개별 동의를 받은 것으로 취급하지 않는다. 기존 동의 시각을 갱신하거나 기존 이용자에게 소급 동의를 부여하지 않는다.

## 주요 수정

- 이용약관: 무료·광고 미운영, 회원·비회원 기능, 외부 콘텐츠 권리, AI 분석의 표본·오류 한계, 게시물 이용 범위, 삭제·신고·이의제기, 비례적인 제재, 법령에 따른 책임, 개정 절차.
- 개인정보처리방침: Google 식별자와 세션, 비회원 작성자 식별정보, Cloudflare 채팅, 최근 30건 보관, 탈퇴 정보, 쿠키 기간, 위탁과 외부 로그인, 국내 DB와 외부 처리 구분, 외부 공개 게시물 분석, 정보주체 권리.
- 과도한 면책과 이용자의 일괄 배상 문구 제거. 광고·추적에 대한 포괄 동의 문구를 두지 않았다.
- 탈퇴 전 DB trigger로 해당 회원의 곡소리방 글·댓글을 삭제한다. 기존 `ON DELETE SET NULL`이 작성자 닉네임·본문을 남기는 문제를 방지한다. 기존의 작성자 없는 글을 일괄 삭제하지는 않는다.
- ISO 타임스탬프 날짜 포맷 오류 수정. 공고일·시행시각을 한국 시간으로 표시한다. 이미 철회된 버전은 그 상태를 표시한다.

## 확인된 한계와 다음 작업

1. 국외 처리 내역 확정: Supabase 서울 DB는 확인했다. Vercel `icn1`은 저장소 지침이며 이번에 운영 설정을 재확인하지 못했다. Google·Cloudflare·Vercel·Vertex AI의 실제 처리 국가, 해외 접근·백업·지원 범위, 이전 근거, 수령자 연락처 및 항목별 기간을 설정·계약으로 확인해야 한다. 사업자 본사 소재지를 이전 국가로 추정하지 않았다. 운영자도 별도 자료가 없다고 답했다. 방침은 이 미확정 상태를 공개하며, 완결된 국외 이전 고지로 보고하지 않는다.
2. 보유기간과 파기: GA의 실제 이벤트 보유 설정, 호스팅·채팅 로그·백업 기간을 확인해야 한다. 탈퇴 정보 정리는 로그인 경로에 의존하므로 독립적인 정기 삭제 작업이 필요하다. 비회원 글의 삭제는 내용을 `[deleted]`로 바꾸고 일부 식별 기록을 남기므로 보유 기한과 추가 파기 구현이 필요하다. 채팅에는 시간 기준 만료가 없다. 정책 문구만으로 실제 파기가 구현된 것으로 보고하지 않는다.
3. 출처별 수집 정책: 제목 표시와 원문 링크가 수집·AI 분석의 허락을 대신하지 않는다. 기존 검수에서 지적한 출처별 robots.txt, 이용약관 및 실제 수집·상세조회 경로를 다시 맞추고 필요한 사용 허락·제외 조치를 해야 한다. 이번 변경은 수집기 설정이나 출처 접근 정책을 변경하지 않았다.

확인한 법령: [개인정보 보호법 제28조의8 제2항](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1033215841), [시행령 제31조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034513131). 실제 국외 이전이 있는 경우 단순한 '국외 처리 가능' 문구와 사업자 방침 링크만으로 필요한 고지사항을 대신하기 어렵다.

## 검증

- `.env.example` 기반 production build 및 TypeScript 검사.
- `npx playwright test --config playwright.policies.config.ts`: 날짜 경계, JavaScript 없는 현행 문서·동시 공지, 두 개정본 전문·이전 버전, 잘못된/미공개 버전 차단, 시행 이후 기본 URL 전환.
- `tests/policy-schema.sql`: 일회용 로컬 Supabase Postgres에서 migration 재실행, 공지기간·한국 자정, 회원 삭제와 다른 이용자 글 보존, 댓글 수, 함수 권한 확인. 전체 fixture는 rollback. 운영 DB에서 계정을 삭제하는 테스트는 수행하지 않는다.
- CLI dry run에서 이번 migration 하나만 확인한 뒤 운영에 적용한다. Git 푸시 후 GitHub의 Vercel 상태와 실제 공개 페이지를 별도로 확인한다.

문구 원본은 같은 디렉터리의 날짜별 Markdown이다. 배포 본문은 `supabase/migrations/20261117033957_refresh_legal_policies.sql`, 번호 이력은 `db/migrations/027_refresh_legal_policies.sql`이며 `db/schema.sql`에도 같은 내용을 반영했다. 이미 공개된 버전을 몰래 고치지 말고 이후 실질적인 변경은 새 개정 버전으로 발행한다.
